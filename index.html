Quatro portais, um sistema

Cada perfil entra pela mesma porta e cai no seu próprio painel. O que aparece no menu é filtrado pela mesma matriz de permissões que a API usa para responder — a interface não é a única guarda.

Administração

Secretaria, coordenação e financeiro

Alunos, matrículas, turmas, grade curricular, ocorrências, cobranças, folha de pagamento e relatórios. Folha e salários só para administrador e financeiro — para os outros perfis os campos nem saem do servidor.

Professor

Só as turmas em que leciona

Chamada, lançamento de notas e boletim das próprias turmas. Quem leciona o quê vem da grade curricular, e é ela que autoriza a escrita.

Responsável

Cobranças e boletim dos filhos

Faturas em aberto com multa e juros calculados, histórico de pagamentos e o boletim de cada filho — e de mais ninguém.

Aluno

Notas e frequência

Painel com o próprio desempenho por disciplina e a frequência do ano corrente.

Público

Matrícula on-line

Formulário em etapas para a família preencher, com envio de documentos e consentimento registrado com data e versão do texto.

Rodar na sua máquina

Precisa de Node 22+ e Docker (ou um PostgreSQL 16 acessível). São cinco passos e uns poucos minutos — no fim você entra com qualquer um dos perfis e navega pelo sistema com dados de exemplo.

  1. Clonar o repositório

    git clone https://github.com/gabrielsoaressn/school-management-system.git
cd school-management-system
npm ci

  2. Subir o banco

    docker run -d --name davilla-postgres \
  -e POSTGRES_USER=davilla -e POSTGRES_PASSWORD=davilla \
  -e POSTGRES_DB=school_management -p 5434:5432 postgres:16

  3. Configurar o ambiente

    cp .env.example .env
# edite o .env:
# DATABASE_URL="postgresql://davilla:davilla@localhost:5434/school_management?schema=public"
# NEXTAUTH_URL="http://localhost:3000"
# NEXTAUTH_SECRET= o resultado do comando abaixo
openssl rand -base64 32

  4. Criar as tabelas e os dados de exemplo

    npx prisma migrate deploy   # aplica as migrations versionadas
npx prisma db seed          # dados de exemplo — APAGA tudo antes

  5. Iniciar

    npm run dev
# http://localhost:3000

Por que não há demonstração on-line aqui. Esta página é estática, e o sistema não é: ele precisa de um servidor Node e de um PostgreSQL para autenticar, calcular juros e gravar chamada. Publicar um ambiente de demonstração de verdade exige uma hospedagem com banco (Vercel, Railway, Fly.io ou uma VPS) — o passo a passo de produção está em docs/DEPLOYMENT.md.

Como o domínio funciona

Quatro decisões explicam a maior parte do código — e evitam os erros típicos de sistema escolar.

O ano letivo é uma entidade

Existe exatamente um ano corrente, garantido por índice único parcial no banco. Turma, matrícula, avaliação e chamada pertencem a um ano.

A série está na matrícula, não no aluno

O aluno está no 3º ano em 2026 e no 4º em 2027. É isso que permite histórico escolar e rematrícula com promoção, retenção e transferência.

A grade curricular autoriza o professor

Quem leciona o quê em cada turma é a única coisa que libera lançar nota ou chamada — verificado no servidor a cada requisição.

Dinheiro é Decimal, data é São Paulo

Todo valor é Decimal(10,2), nunca ponto flutuante. Todo “hoje”, vencimento e dia de calendário passa por America/Sao_Paulo explicitamente — inclusive nos testes.

Segurança e LGPD

Sistema escolar guarda CPF de menor de idade, endereço, laudo médico e dado financeiro de família. O tratamento disso é parte do produto.

  • Autorização por matriz de capacidades, aplicada no middleware, nas páginas e em todos os handlers de API — a mesma fonte de verdade nos três lugares.
  • Folha de pagamento e salários restritos a administrador e financeiro; os campos são removidos do payload para os outros perfis.
  • Trilha de auditoria das operações financeiras, exclusões, mudanças de configuração e acessos a listagens com CPF.
  • Exclusão lógica em tudo que contém dado pessoal ou financeiro, com filtro automático no acesso ao banco; exclusão definitiva só por rotina administrativa explícita.
  • Consentimento versionado na matrícula, e a página /privacidade publica finalidades, bases legais, prazos de retenção e o canal de solicitação do titular.
  • Documentos fora da pasta pública: os arquivos enviados na matrícula só são lidos por rota autenticada.
